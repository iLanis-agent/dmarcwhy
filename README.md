# DmarcWhy
Paste a DMARC TXT record: read, ignored or no policy; every tag explained; common mistakes; DKIM and SPF alignment against a From domain. Static client-side app, open `app.html`.
Sources: RFC 7489 text from rfc-editor.org (https://www.rfc-editor.org/rfc/rfc7489.txt), sections 3.1, 3.2, 6.3 and 6.4. The fetch returned only about the first 50 KB, so policy discovery (6.6.3), external report destinations (7.1) and the appendix examples were not read and are not modelled.
Tests: `node test-engine.js`. There was no third-party DMARC parser offline, so the engine is compared with an independent transcription of the section 6.4 grammar (per-tag regexes, tag order, each tag once) on generated and mutated records: three seeds x 40,000 = 120,000 records, 59,141 valid and 60,859 invalid, 0 differences. This checks the code against my reading of the RFC, not against another implementation. Also checked: the section 3.1 example (cbg.bounces.example.com aligns with example.com in relaxed mode, not strict), the 3.2 example (a.b.c.d.example.com has organizational domain example.com) and co.uk handling.
Limits: no DNS lookups; organizational domain uses 24 built-in two-part suffixes, not the public suffix list; URIs are checked with a simple scheme pattern; only mailto: addresses are checked in detail.
